## Architecture & Integration Notes

- **Calibre Database Access**: The Calibre library SQLite database (`metadata.db`) operates in WAL mode and supports concurrent readonly queries via `bun:sqlite` (`new Database(CALIBRE_DB_PATH, { readonly: true })`). When running `calibredb` CLI commands while `calibre-server` is running, `--with-library http://127.0.0.1:8088` must be passed to avoid locking errors.
- **Web Scraping & Proxy**: Outbound HTTP requests to external web articles route through Sing-box LAN proxy at `http://127.0.0.1:7890`. For paywalled or Cloudflare-protected sites, use Jina Reader (`https://r.jina.ai/<url>`) with header `X-Return-Format: markdown`. Do not send browser `User-Agent` strings to Jina Reader as its gateway may reject them with HTTP 403.
- **Paywall & Navigation Filtering**: Article extraction (`uploader/article.ts`) rejects subscription barrier pages (link density > 50%, prose < 150 words, subscription pricing markers) before EPUB generation to prevent garbage imports into Calibre. Navigation lists and tags (`<map>`, `<area>`, `<nav>`, `<header>`, `<footer>`, `<aside>`) are aggressively stripped.
- **Telegram Formatting Resilience**: Telegram Markdown parsing mode fails with HTTP 400 on unescaped special characters (`_`, `*`, `[`). Always guard `sendMessage`, `editOrSendMessage`, and `sendDocument` with automatic plain-text retry on HTTP 400.
- **Module Exports & Polling**: The Telegram bot script (`uploader/bot.ts`) guards `pollTelegram()` with `if ((import.meta as any).main)` so helper functions can be safely imported without starting conflicting polling loops.
- **WAN Reverse Tunnel & Mini App**: Reading HQ dashboard is exposed via persistent SSH reverse tunnel (`com.ospeto.reading-vless-tunnel.plist`) through Sing-box SOCKS5 (`127.0.0.1:7890`) to the cloud VPS, reverse-proxied by Caddy at `https://reading.wavypremium.xyz`. The bot registers a native Telegram Web App menu button via `setChatMenuButton` on startup and handles `/app` and `/webapp`.
- **TMA Asset & UX Optimization**: `uploader/index.html` embeds pre-compiled static minified Tailwind CSS and an inline SVG symbol sprite, removing runtime CDN compilation (`cdn.tailwindcss.com`) and external font requests. Native Telegram WebApp integration synchronizes `Telegram.WebApp.themeParams`, viewport height (`--tg-viewport-height`), `HapticFeedback`, and binds `BackButton` to close active drawers/modals. The catalog uses `sessionStorage` stale-while-revalidate caching and progressive rendering (`PAGE_SIZE = 36` with `IntersectionObserver`) for mobile DOM efficiency.
- **Calibre Cover Setting & Native Thumbnail Cache**: When updating covers on existing books, `calibredb set_metadata` expects `--field cover:<path>` (`--cover` is only supported on `calibredb add`). Subprocess execution must always strip proxy environment variables (`HTTP_PROXY`, etc.) to prevent `calibredb` output pollution. Native thumbnail generation downscales covers via `/usr/bin/sips -Z <width>` cached under `/Users/ospeto/uploader/cache/covers/` with immutable HTTP caching headers and ETags.
- **Tunnel Auto-Healing Watchdog & Health Dashboard**: The reverse SSH tunnel forwards both Reading HQ (`8086`) and KOSync (`7200`) to VPS `panel`. LaunchAgent `com.ospeto.reading-tunnel-watchdog` runs `scripts/tunnel-watchdog.sh` every 120s, healing stale remote listeners via `fuser -k` and kickstarting the tunnel daemon, with Telegram alerts after 3 consecutive failures. In-chat `/status` and `/health` commands render live metrics across WAN, tunnel, Calibre, KOSync, and Mac Mini host with interactive callback refresh.
- **Telegram Bot Interactive Dashboard & Shelf**: `/menu` and `/start` present an interactive inline keyboard dashboard linking to the TMA web app, library search, recent additions (`/recent`), currently reading shelf (`/reading`), server status, and hot SQLite backups. Ingested books and articles attach a 1-row action bar (`send_book:<id>`, TMA link, `delete_book:<id>`). `/reading` queries `koreader-sync.db` for active reads (`0 < percentage < 0.99`) rendering progress bars (`████░░░░ 45%`) and one-tap file delivery buttons mapped to Calibre.
- **Dual WAN Endpoints & KOReader Sync**: The reverse SSH tunnel forwards both Reading HQ (`8086` -> `https://reading.wavypremium.xyz`) and KOSync (`7200` -> `https://kosync.wavypremium.xyz`) via VPS Caddy (`http://172.18.0.1:7200`). KOReader devices on cellular or outside home Wi-Fi configure Custom Sync Server as `https://kosync.wavypremium.xyz`; direct LAN access remains at `http://192.168.31.15:7200`.
- **Tunnel Forwarding Collision Recovery**: The tunnel script uses `-o ExitOnForwardFailure=yes`. If launchd restarts the tunnel before VPS `sshd` reaps the previous session, port binding fails with `Error: remote port forwarding failed for listen port <port>`. Stale remote listeners must be cleared on the VPS (`fuser -k 8086/tcp 7200/tcp`) to allow the tunnel to bind cleanly.
- **Production Deployment Topology**: Live services execute out of `/Users/ospeto/uploader/` under launchd (`com.ospeto.reading-telegram-bot`, `com.ospeto.book-uploader`, `com.ospeto.reading-vless-tunnel`, `com.ospeto.reading-tunnel-watchdog`). After landing PRs on `main`, changes must be synced from the repository to `/Users/ospeto/uploader/` and the bot reloaded with `launchctl kickstart -k gui/$(id -u)/com.ospeto.reading-telegram-bot`.
- **Public WAN Hardening & LAN Exemption**: Reverse tunnel WAN requests (`reading.wavypremium.xyz`) require authentication on mutating routes (`POST`/`DELETE`) via Bearer token (`READING_API_KEY`), Telegram WebApp HMAC `initData`, or session cookie; local LAN requests (`192.168.x.x`, `127.0.0.1`) pass friction-free. Missing or ambiguous headers fail closed as WAN. Origin and Host checks strictly validate IPv4 octets (`isPrivateIPv4`), rejecting lookalike domains (`192.168.attacker.example`). API keys in query strings (`?token=`) are rejected. State-changing cookie mutations strictly require valid Origin or Referer. Outbound fetches block private/metadata IPs with hop-by-hop redirect validation and response byte caps (`safeFetchWithSsrf`).
- **Durable Ingestion Queue & Calibre Mutex**: URL ingestion, uploads, archives, and Telegram bot ingestion route through the durable SQLite queue (`jobs` table in `cache.db`). The queue uses worker leases with heartbeats, resets retry counts on manual retry, and recovers stale/hung jobs on startup. Public job inspection payloads redact filesystem paths and secrets. Mutating Calibre CLI writes are serialized via `withCalibreLock` / `withCalibreLockSync` across processes.
- **EPUB-Only Canonical Policy**: Collection accepts and imports only `.epub` files, enforced via both filename extension and ZIP container validation (`validateEpubContent`). Upload bodies are stream-metered up to 100MB (`meterStream`). Calibre library files are never renamed on disk by hand; user-facing downloads derive sanitized filenames (`Title - Author.epub`) dynamically from metadata.
